# RxCheck Failure Mode Analysis

This document summarizes likely failure modes for the current prototype. It is not a formal hazard analysis. It is meant to support design science evaluation and conservative manuscript discussion.

| Failure Mode | Risk | Current RxCheck Behavior | Code Evidence | Remaining Limitation | Future Improvement |
|---|---|---|---|---|---|
| LLM unavailable or API key missing | User cannot generate plain-English explanation. | Missing `ANTHROPIC_API_KEY` raises a clear runtime error and the API maps it to HTTP 400. Structured interaction findings still exist. | `app/services/llm.py::generate_explanation`; `app/api/interactions.py::explain_finding`. | Network/provider failures after request start are not queued, retried, or persisted as failed explanation jobs. | Add retry/backoff, failure-state persistence, and UI copy that structured findings remain authoritative. |
| OpenFDA unavailable | Label excerpts may be unavailable or explanation generation may fail if an HTTP error propagates. | OpenFDA 404 returns `None`; other HTTP errors call `raise_for_status()`. OpenFDA is not used for interaction detection. | `app/services/openfda.py::_fetch_label_by_query`; `app/services/llm.py::generate_explanation`. | No robust fallback around non-404 OpenFDA failures; no local SPL mirror. | Wrap OpenFDA failures as non-fatal context loss; persist label cache in a versioned `spl_documents` table. |
| RxNorm failure during medication entry | Medication normalization may fail, slowing or blocking medication addition. | RxNorm requests raise on HTTP errors; if no match is found, unresolved entries and placeholder drugs are created. | `app/services/normalization.py::_rate_limited_get_json`; `_record_unresolved`; `app/api/patients.py::create_patient_medication`. | Network exceptions are not gracefully converted into a placeholder path. | Catch RxNorm network errors and create a clear unresolved placeholder with warning. |
| Unresolved placeholder drug | Interaction results may be incomplete because the unresolved medication is excluded. | Placeholder drugs remain in medication list but are filtered out of checks. UI shows an unverified badge. | `Drug.is_placeholder`; `app/services/orchestrator.py` active-med query; `frontend/src/components/MedicationList.jsx`. | Users may overtrust results if they miss the warning that unresolved drugs were excluded. | Add check-result warning listing excluded placeholder medications. |
| Missing database interaction | A clinically real interaction may not appear if it is absent from imported data. | The orchestrator returns no finding. It does not ask the LLM or OpenFDA to infer missing interactions. | `app/services/orchestrator.py`; `app/services/llm.py` only runs after a finding exists. | Absence of a row can be misread as absence of clinical risk. | Add clearer UI disclaimer and source-coverage display. Validate imported data against reference scenarios. |
| DDSI without matching patient condition | False-positive drug-disease alerts could occur if DDSI is not condition-gated. | Current DDSI query requires a matching active `patient_conditions.condition_id`; patients with no conditions get no DDSI findings. | `app/services/orchestrator.py` DDSI query. | Depends on accurate, complete condition entry. | Add structured condition import, terminology mapping, and tests for active/resolved condition states. |
| Acknowledgment suppression | A reviewed interaction might be hidden too aggressively. | Suppressed interactions are still returned with `suppressed=true` and shown in a collapsible section. Suppression applies only when acknowledgment severity is at least current severity. | `app/services/orchestrator.py`; `frontend/src/components/InteractionResults.jsx`; `app/models/audit.py::InteractionAcknowledgment`. | No UI explaining severity-escalation invalidation; no expiry management view. | Add reviewed-alert management screen and explicit suppression rationale. |
| Override persistence | A pharmacist may think an override changes future checks. | Overrides are persisted and audit events are written, but orchestrator does not use overrides to suppress or alter future checks. | `app/api/interactions.py::override_finding`; `app/models/audit.py::InteractionOverride`; `app/services/orchestrator.py`. | Override semantics are documentation-only in current prototype. | Decide and document whether overrides should suppress, annotate, escalate, or remain audit-only. |
| Prompt injection risk | External label text or user-entered text could influence the LLM. | The prompt instructs the model to use only context and return JSON; drug mentions are cross-checked. | `app/services/llm.py::PROMPT_SYSTEM`; `_validate_drug_mentions`. | No prompt-injection sanitizer, no strict output schema enforcement beyond custom parsing, no citation-level verification. | Add context sanitization, JSON schema/Pydantic validation, source-specific citation checks, and adversarial tests. |
| No authentication | Anyone reaching the service can use patient and interaction endpoints. | No login, session, JWT, route guard, or role enforcement exists. A default user is created for prototype actions. | `app/api/patients.py::ensure_default_user`; absence of auth middleware in `app/main.py`. | Not suitable for real patient data or clinical deployment. | Add authentication, authorization, audit identity binding, and row-level access controls. |
| Database unavailable | App startup or requests fail because SQLAlchemy cannot connect. | `Base.metadata.create_all(bind=engine)` runs at import/startup; runtime DB calls assume connectivity. | `app/main.py`; `app/db/session.py`. | No degraded read-only mode or graceful startup health state. | Add migration-managed startup, health checks that report DB status, and operational runbooks. |
| Import data quality issue | Incorrect alias mapping or unresolved DDInter names can omit interactions. | Importer loads local alias map and quarantines unresolved rows. | `scripts/import_ddinter.py::load_alias_map`; `resolve_rows`. | Quarantine output is printed but not persisted as a formal review queue. | Persist import quarantine rows and add import validation reports. |
